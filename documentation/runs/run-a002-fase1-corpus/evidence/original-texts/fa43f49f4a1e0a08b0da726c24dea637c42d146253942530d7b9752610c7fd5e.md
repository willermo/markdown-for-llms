### GPT-R010-I001: formula chiusa della label riattivata come HTML

Raw minimo di prova (il bundle contiene anche heading e paragrafo finali):

```markdown
È See [Known $x `first
second` <img src="../outside.png"> y$ words](https://example.invalid) end.

# Visible heading

After words.
```

`markdown_link` accetta la label e il code span che attraversa LF. Il consumer
ricorsivo passa l'intera label con producer_limit=len(label); math_end vi
riconosce `$…$` chiusa e conserva raw `x `first\nsecond` <img …> y` come formula.
La struttura matematica è fuori subset, esplicitamente diagnosticata: ciò
non rende HTML il corpo della formula lessicale chiusa. Il walk esterno
invece limita bound alla prima LF quando labels è attivo, non trova il `$`
di chiusura, salta il code tramite ledger e produce l'evento img a char31.
La nuova inline_html_events valida quell'img prima della ricorsione.

v9: audit COMPLETE, formula raw preservata (start13/byte14 nel paragrafo),
link https://example.invalid e tre blocchi tipizzati. v10: audit
INCOMPLETE/UNSAFE_REFERENCE, detail `Path evasivo: '../outside.png'`; osservazione
fallback observations-v1 con unico unknown dell'intero documento, formula/ref
vuoti. La variante script ha lo stesso effetto. È perdita della proiezione
tipizzata, non perdita del raw sul disco. Non deduco un exit CLI proprio.

[Diagnostics v10](../evidence/review-implementation-r010-chatgpt/out-decisive-v10-001/math-code-label-paragraph-img/diagnostics.json)
e [v9](../evidence/review-implementation-r010-chatgpt/out-decisive-v9-001/math-code-label-paragraph-img/diagnostics.json)
mostrano medesima label accettata. Otto varianti × quattro host nei summary.
Due controlli con identico math/code **fuori label** preservano formula e non
visitano HTML su entrambi i reader. Questo non chiede label universali:
una label con LF puro non accettata non è un finding. L'errore iniziale nei
miei otto attesi ref riguardava proprio quel caso e fu corretto separatamente.

### GPT-R010-I002: ledger della label applicato dentro l'owner HTML

```markdown
È See [<span>`<script>x</script>`</span>](https://example.invalid) <img src="../second.png">
```

Nel profilo ricevuto span aperto possiede contenuto HTML finito: i backtick
interni sono testo HTML, non code Markdown. Il controllo senza img successivo
rileva correttamente script anche su v10. Nel raw sopra, label_codes registra
13→33; markdown_lexemes lo salta incondizionatamente prima del ramo html_stack.
Gli eventi v10 contengono span e img esterno, **non script interno**. La guardia
anticipata raccoglie la violazione img e solleva prima di inline(label).

v9: prima diagnosi `HTML attivo/sconosciuto: script`. v10: `Path evasivo:
'../second.png'`, visite dirette solo span,img. Invertendo i payload (img
`../first.png` dentro span, script successivo) v10 riferisce script, v9
`../first.png`. Il difetto vale nei quattro host. Classificazione UNSAFE e
score FAIL restano; l'impatto è la copertura della guardia e l'ordine delle
diagnosi espressamente richiesti, non una lettura esterna riuscita.
