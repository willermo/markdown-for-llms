## E01 — Struttura matematica limitata e diagnostica raw

**CLA-P001.** Ragione: grafie LaTeX alternative possono descrivere la stessa
struttura, soprattutto dopo lettura OMML/MathML. Sostituire il gate di uguaglianza
dei token raw con `math-structure-v1`; conservare sempre TeX originale, offset,
code point, token e diff raw come diagnostica, senza usarli da soli per bocciare
una variante ammessa. Non si deduce equivalenza semantica dalla struttura.

### Schema, grammatica e origine del gold

Il gold di ogni formula ha `formula_id`, contesto inline/display, locatori del
sorgente, `reference_latex` leggibile, `structure_expected` e mappa tra foglie
e simboli/numeri originali. La struttura attesa viene **redatta esplicitamente**
dalla specifica matematica leggibile dall'autore, controllata da M sul sorgente
canonico e da V per la resa visiva. Non viene calcolata dal converter, dal reader
Markdown o dal parser `math-structure-v1` che si sta valutando. Per OMML/MathML
si conservano anche i sottoalberi sorgente con locator/hash. Un validatore comune
di schema dati è ammesso; lexer/parser e logica di confronto non sono condivisi
con il verificatore M.

Schema strutturale minimo (campi mostrati integralmente per ogni tipo):

```text
Seq(items: ordered Node[])
Symbol(value: exact single letter)
Number(lexeme: exact digits with optional decimal part)
Operator(kind: plus|minus|equals|lt|gt)
Group(body: Seq, kind: braces|round|square)
Scripts(base: Node, sub: Arg|null, sup: Arg|null)
Fraction(numerator: Arg, denominator: Arg)
Sum(lower: Arg|null, upper: Arg|null)  # il corpo segue nella Seq, senza scope inferito
Text(value: exact decoded text, command: text)
Arg(body: Seq)                       # confine di argomento TeX conservato
Aligned(rows: ordered Seq[] of ordered cell Seq[])
Matrix(delimiter: none|square, rows: ordered cell Seq[][])
```

Numeri non convertiti a float: `007`, `7`, `1.20`, `1,20`, `120` restano distinti.
Le cifre sono ASCII nel sottoinsieme di formula; un'altra cifra Unicode non
diventa automaticamente equivalente. In una formula `1e-3` senza costrutto
esplicito è la sequenza numero/simbolo/operatore/numero, non una riscrittura
in notazione scientifica. Il segno è un nodo operatore distinto, non viene
assorbito nel lessico numerico. Virgola/punto decimal richiedono cifre adiacenti,
sono conservati; altri usi ambigui della virgola sono UNAVAILABLE.

Grammatica finita, senza macro espanse, operatore di precedenza o CAS:

```text
math     := sequence | aligned | matrix | matrix_wrapper
sequence := item+                         # ordine testuale, nessun riordino
item     := operator | atom scripts?
atom     := symbol | number | text | group | fraction | sum
symbol   := one ASCII letter
number   := digit+ (('.'|',') digit+)?
operator := '+' | '-' | U+2212 | '=' | '<' | '>'
scripts  := ('_' arg ('^' arg)? | '^' arg ('_' arg)?)
arg      := '{' sequence '}' | one_TeX_atom
group    := '{' sequence '}' | '(' sequence ')' | '[' sequence ']'
fraction := '\frac' arg arg
sum      := '\sum' scripts?               # sub/sup diventano lower/upper
text     := '\text{' literal_text '}'     # spazi/code point esatti
aligned  := '\begin{aligned}' row ('\\' row)* '\end{aligned}'
matrix   := '\begin{matrix}' row ('\\' row)* '\end{matrix}'
          | '\begin{bmatrix}' row ('\\' row)* '\end{bmatrix}'
row      := sequence_or_empty ('&' sequence_or_empty)*
matrix_wrapper := '[' matrix ']' | '\left[' matrix '\right]'
```

`one_TeX_atom` consuma un solo token TeX: lettera o cifra singola, oppure un
costrutto fraction/text/sum con i suoi argomenti dichiarati. Non consuma tutto
un identificatore o una sequenza di cifre. Pertanto `x_12` contiene subscript1
e successivo2, mentre `x_{12}` contiene subscript12: **non equivalenti**.
Un argomento braced viene memorizzato come Arg/Seq; un gruppo fuori dalla
posizione di argomento resta Group. Mai cancellare tutte le graffe.

Le righe/celle sono quelle effettivamente osservate, incluse vuote. Una matrice
ragged, riga/cella eliminata o formula con riga mancante resta una struttura
osservata con shape/difetto, confrontabile e FAIL; non riempire celle dal gold
né classificare automaticamente come unsupported una perdita riconoscibile.
Riga terminatrice vuota aggiunta da `\\` finale non viene eliminata: resta
osservata e produce differenza. Dimensioni osservate non vengono dal gold.

### Regole di confronto contestuali

| Regola | Trasformazione limitata della vista strutturale | Protezione e diagnostica |
| --- | --- | --- |
| F01 argomento braced/singolo | `_i` e `_{i}`, `^2` e `^{2}`, `\frac ab` e `\frac{a}{b}` costruiscono gli stessi Arg | `{i+1}` conserva tutta la Seq, non è `_i+1`; bare token consuma una cifra/lettera, non una parola |
| F02 script labels | Una sola sub e sup per base; ordine `_i^2`/`^2_i` raccolto nei campi distinti | Duplicati di script restano difetto sintattico; cancellare/cambiare un campo è FAIL, niente modifica del base |
| F03 whitespace TeX | Ignorare U+0020/tab/LF/CR **nel lexer math**, fuori Text; `\,`, `\:`, `\;`, `\!`, `\quad`, `\qquad` registrati come spazi tipografici, non nodi di contenuto | Text, codice, prosa e celle non math invariati; token whitespace raw e resa tipografica restano disponibili |
| F04 meno | U+002D e U+2212 producono `Operator(minus)` solo in math | Plus, assenza segno o posizione diversa FAIL. In `\text`, prosa, codice, URL e testo di cella confronto code point esatto |
| F05 matrice delimitata | `bmatrix` e matrix racchiusa **interamente** in `[...]` o `\left[...\right]` producono Matrix(square,rows) | Nessuna rimozione di parentesi di una cella; matrix non delimitata diversa da square; parentesi round non equiparate |
| F06 testo dentro formula | `\text{...}` contiene la stringa effettiva, escape letterali `\{`, `\}`, `\%`, `\$`, `\_`, `\&`, `\#` espliciti | Non collassare spazi, NFC/NFD, meno o contenuto Text; macro annidata o linebreak TeX dentro Text non gestiti UNAVAILABLE |

F03 elimina solo token di spazio già riconosciuti, non caratteri prima della
tokenizzazione: non concatenare due lessemi numerici attraverso un comando
di spacing. `1\quad2` osserva N(1),N(2), distinti da N(12); `- 007` conserva
N(007) e minus. Questo vincolo protegge i numeri sensibili anche nel confronto
strutturale; ulteriori positivi/negativi autonomi sul confine token richiesti.

Limiti: sottoinsieme per le formule dichiarate del corpus e controlli, massimo
4096 code point/formula, profondità16 e 256celle. Macro ignote, ambienti diversi,
`\boldsymbol`, comandi stile non dichiarati, delimitatori dinamici non previsti,
commenti TeX, `\verb` o parsing ambiguo→UNAVAILABLE con motivo/offset/raw.
Il payload verbatim resta intatto, senza normalizzazione; non tentare una
valutazione parziale che dia PASS alla formula intera. Se alcune foglie note
mostrano già una perdita, riportare anche FAIL del controllo locale verificabile,
senza occultarlo con l'unsupported circostante. Schema del risultato distingue
`fully_supported` da `recognized_defects` e diagnostica.

Metriche: 100% formule strutturalmente uguali, 100% operatori/argomenti/numeri,
righe/celle e delimiter; denominatori del gold invariati per formule mancanti
o unavailable, con stati distinti. Numeri in matematica allineati per
`formula_id + node_path`, lessico esatto e operatore di segno nella struttura;
fuori matematica restano occorrenze/code point esatti del piano originale.
Testo/CER della prosa non ingloba payload LaTeX o delimitatori math: ha solo
i segmenti testuali osservati, con offset e denominatore separati. Raw della
formula resta diagnostico, così un positivo F01/F04 non fallisce di nuovo per
il CER o per il gate numerico non contestualizzato. Un numero in una cella
testuale non diventa math senza un vero nodo math osservato.

locatori sorgente, non riusa `math-structure-v1` sugli output. TXT/code-point

`m_required`, `v_required`, `observable_in_canonical`, locator e reason.

dal font non è attestata: code-point-preservation `NOT_APPLICABLE` sul raster,
trascrizione Unicode **convenzionale** dichiarata separatamente. CER rispetto
a tale trascrizione è una misura del testo atteso, non recupero certificato
dell'encoding originale; zero-error può attestare solo quella convenzione.

del generatore e nuova revisione, senza inventare una prova dal progenitore.

locator, evidence_kind, expected, actual, codepoints, method/tool/hash,
status=PASS|FAIL|DIVERGENT|UNAVAILABLE|NOT_APPLICABLE, reason, evidence_paths`.

qualunque required FAIL→FAIL, altrimenti required unavailable/divergent→INCOMPLETE.

di verificare testo/segno visibile. Le proprietà provenance hanno un gate
separato e non gonfiano gli elementi di testo accuratamente misurati.

le identità coincidono; REJECTED su required FAIL/reject, altrimenti PROVISIONAL
con dettaglio proprietà/giudizi pendenti. Un giudizio invalido per hash diverso
è STALE e non riutilizzato. Totali corpus esprimono verified/provisional/rejected,
non una firma globale che sani i documenti incompleti. Per regioni raster
VERIFIED riguarda trascrizione visibile e provenance, con code point originari
non attestati esplicitamente nel record; nessuna certificazione nascosta.

### Corpus, controlli e giudizi output: ambiti distinti

Riutilizzabili fra ripetizioni solo con identici byte bundle/config pertinente

## E03 — Harness ufficiale, expected-exit 0 e stati conservati

**CLA-P003.** Il target ufficiale di R è un harness proprio, proposto in
`scripts/benchmarks/campaign.py`, non il comando benchmark il cui exit varia
con la qualità del motore. `R --expected-exit 0` viene fissato **prima** della
campagna; non adattarlo all'exit osservato. R continua a richiedere isolamento,
preflight, assenza timeout/violazioni e controlli sui figli. Un harness corretto
può terminare0 rendicontando un motore FAIL; non può trasformare quel FAIL in PASS.

### Contratto del manifest e dei record

Prima dei tentativi identificare/hashare `campaign-manifest.json`: versione
schema/protocollo, experiment_id, input/gold/config/tool/S/B/I e manifest
esterno wheel, elenco esatto dei percorsi/ripetizioni e test case, expected
degli **assert** dei controlli, expected harness0 per R, deadline e riserva.
Gli exit benchmark0/2 e score0/3/5 sono possibili osservazioni della baseline,
non attesi di fedeltà: il motore non deve essere costretto a PASS. L'exit4
è ammesso solo per un negativo input/contratto dichiarato a priori, mai come
successo di un tentativo baseline. Nessun catch-all di exception→record verde.

Tre schemi minimi, validati prima di aggregare:

- Tentativo: identità/hash obbligatori, input/config effettivi, engine_exit
  oppure null con reason (legacy), signal/timeout; benchmark_run_exit e
  score_exit separati; conversion, bundle, quality, support; raw/hash/inventario,
  audit/findings e metriche con denominatori/stati; errore con stage/type.
- Caso di controllo: case_id, mutazione/input immutati, expected exit/stato/
  rilevatore **prima** della chiamata, actual e dettagli verificati, assertion
  PASS/FAIL. Il successo di un negativo è l'assert della perdita specifica,
  non la mera esistenza di JSON o l'exit diverso da zero.
- Receipt harness: manifest_digest, ordered planned/observed attempt_id e
  case_id, verifiche hash/schema, record mancanti, batch/status/qualità reali,
  `execution_complete`, `contract_valid`, test assertions, harness_exit,
  deadline/figli raccolti, errori e paths. Scrittura atomica della receipt
  finale, registri parziali preservati su crash; niente receipt finale inventata.

`execution_complete=true` significa tutte le osservazioni e verifiche previste
registrate: **non** batch COMPLETE, qualità PASS o A10 soddisfatto. Batch,
bundle e qualità restano gli stati del piano. Un output unsafe riconosciuto
è un risultato audit valido; un auditor che va in exception o non può accertare
integrità ha errore harness. Record valido richiede evidenze effettivamente
disponibili, o assenza attesa con reason verificabile; mai hash fittizio di raw
non leggibile. Un record mancante non è convertito in NOT_MEASURED.

Exit CLI risultanti: `run`0/2/4/130 come piano; `score`0(PASS),3(FAIL),5
(indeterminate/not-measured/required unavailable),4(contratto). Per il comando
combinato `evaluate`, prevalenza4→2(incomplete operativo)→3→5→0. Anche quando
evaluate2, conservare score3/5 e stati separati nei record; non perdere qualità.

### Argv/config e controlli autonomi

Argv diretto mantiene `--wrap=none`, `--markdown-headings=atx`, data-dir

completa sopra. `--from` esplicito docx/epub/rtf/latex, senza estensioni input

rifiuta macro dinamiche/definizioni/include non allowlisted; l'expander proprio
gestisce soltanto le inclusioni dichiarate, non il reader Markdown. Non
presumere che un flag extension del writer sia disponibile su ogni reader.
Ogni reader/source validator/versione/config è hashato; nessun filtro,
template, Lua o backend implicito. Eventuale `--sandbox` compatibile resta
decisione operativa del piano e viene testato prima, senza indebolire R.

Config hash: serializzazione canonica UTF-8, keys ordinate, versione schema,
enabled/disabled completi, extension-inventory digest, ordered writer argv,
input reader, adapter/reader/math hashes, pandoc absolute/resolved hash,
options comuni e sicurezza. Cwd/output unici nei record di tentativo; template
di argv hashato e argv effettivo completo registrati. Legacy riceve esattamente
lo stesso writer e opzioni consentite nei campi config esistenti, E08; eventuale
divergenza effettiva è nuova config distinta, non un confronto equivalente.

senza i documenti/gold del corpus: P01 quote/dash/NFC e smart-off; P02 tabella

P06 attrs header/fragment presente e assente; P07 span/div annidato con anchor;

P11 HTML passivo table/span/text e unsafe; P12 raw TeX label/ref/unknown;

## E06 — Input invalido e output unsafe sono esiti diversi

**CLA-P006.** Validator input prima del primo tool: input non confinato,
archivio/include/XML/HTML invalido o limiti violati→exit4, nessuna conversione.
Per baseline è H09, per negativo dichiarato H08. Il record di rifiuto contiene
locator/reason/hash sicuri, tool_not_started; non inventare raw/observations.

Output prodotto da un motore che contiene un riferimento unsafe: preservare
raw accessibile e bytes immutati, registrare finding con raw offset e stringa
destinazione; **non** seguire, aprire, copiare target, traversare o acquisire
risorse. Bundle `INCOMPLETE`, reason `UNSAFE_REFERENCE`, run/evaluate2,
quality FAIL/score3, batch PARTIAL/FAILED. Conversion può essere SUCCESS se
exit0 e Markdown leggibile, distinto dal bundle. Un errore motore già presente
si conserva insieme ai finding. Il runner non modifica il link per renderlo
sicuro né riclassifica tale output come input invalido/exit4.

Audit path: componenti lessicali prima di risoluzione; reject assoluti anche
se puntano apparentemente dentro root, drive/fileURI/backslash evasivi/`..`,
percent-encoding ambiguo/traversal. `lstat` solo su discendenti con parent
regolari verificati, non `resolve` seguito da open su target ignoto. Symlink:
inventario lstat/readlink **del link stesso**, target stringa inerte, nessun
digest del file destinazione; interrompere discesa. Niente hash di target
esterno, anche se presente/accessibile. Directory root e parent non symlink;
asset richiesto regular e confinato, apertura no-follow e controllo identità
prima/dopo dove disponibile. Hardlink evasivo non attestabile→rifiuto/limite,
mai dichiarare confinamento solo dal nome. Archivi non estratti prima dei check.

Raw Markdown regular accessibile nella root viene hashato/preservato anche se
testo unsafe. Se output atteso è esso stesso symlink, non leggerne il target:
preservare metadata/link-stringa e stdout/regular raw disponibili; raw file
UNAVAILABLE con motivo, non fittizi bytes. Non è obbligo di leggere un file
estraneo per adempiere alla conservazione. Se si rileva invece **scrittura
effettiva fuori dal confine**, tampering o impossibilità di audit, errore
integrità H10/H11→harness4/R non accettato; non sanarlo come semplice motor-loss.

Rendicontazione sicura: escaping HTML/Markdown di destinazioni, code point
e symlink-stringhe; preview raw come testo o allegato inerte. Nessun link attivo
a target non validato, nessun img src ricavato dall'output unsafe, URI esterna
mostrata come stringa (non fetch). Non inserire contenuti script/style in packet;
solo file regular locali verificati come navigazione/media. Anche riferimento
esterno legittimo è dato da confrontare, non richiesta di navigazione del runner.
