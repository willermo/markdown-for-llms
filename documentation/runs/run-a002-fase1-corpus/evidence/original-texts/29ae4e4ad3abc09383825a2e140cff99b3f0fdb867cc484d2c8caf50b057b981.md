## Nota tecnica prima delle modifiche al prodotto

Il lexer markdown_lexemes possiede già il dominio sorgente e decide quali
code/math/label/destinazioni/metadata chiusi e quali token sono inerti. Dopo
un delimitatore incompleto avanza del solo opener e riconosce aperture HTML
reali. Il consumer inline crea invece unknown fino a leaf_end, perdendo quelle
aperture e il flag resource_syntax. HTMLTree riceve poi tutta la coda prima
di scegliere il primo subtree: valida anche code Markdown esterno alla
foglia HTML. La successiva validate_html sulla stessa coda ripete il difetto.
Il mapping char/UTF8 r009 è esplicito e non va ricostruito o sostituito.

Scelta locale: rendere disponibili dal medesimo walk le aperture HTML e i
limiti delle foglie HTML, rispettando gli atomi Markdown chiusi e le barriere
opache sorgente. Nel dominio inline già deciso dal producer, la validazione
precede ogni proiezione/fallback e visita tutte le aperture effettive in
ordine sorgente; un unknown non le nasconde. La proiezione HTML usa soltanto
l'intervallo della propria foglia, non la coda Markdown. Se il fallback
perde una risorsa sicura riconosciuta, conserva almeno una diagnosi esplicita
resource_syntax/INCOMPLETE; non è autorizzato COMPLETE con asset perduto.
La guardia dei producer HTML blocco/raw e l'estensione F36 restano distinte
al dominio Markdown, senza un secondo feed puro obbligatorio. B1–B4 saranno
UNSUPPORTED con corpo opaco anche quando HTMLParser puro riconosce aperture:
limite deliberato da documentare, non esteso ai fallback Markdown F43.

Invarianti: guardia sulle aperture effettive prima di unsupported; nessuna
apertura inventata da code/math chiusi, token o attributi; proprietà della
foglia HTML prima di feed/proiezione; nessuna chiusura presa da un producer
estraneo; stessi raw/char/UTF8 e blocchi esterni. F40/F41 e matrice308 restano
contratti già provati, con nuove regressioni sui byte finali. Scorer, corpus,
gold, raw, V13/A03 e storia/review/snapshot ricevuti restano protetti.

Il codice nuovo invalida prove del reader: nuovi S/B/I/build/wheel canonica/
reinstallazione e dieci hash, confronto v9 fisico con identici oracoli,

### Esito dei rilievi

- F43: il medesimo lexer rende disponibili tutte le aperture HTML riconosciute
  nel dominio inline prima che una foglia unknown possa nasconderle. La guardia
  PassiveHTML precede proiezione/fallback, conserva la prima violazione in
  ordine sorgente e prosegue la visita. A1/A2/A3/A4/A5/A6/A7/A8/A10 unsafe,
  detail e score3/run/evaluate2, nessuna apertura evasiva. A9 sceglie
  l'alternativa autorizzata INCOMPLETE/UNSUPPORTED_RESOURCE_SYNTAX: risorsa
  sicura persa esplicita, senza lettura o immagine inventata. Code/math chiusi,
  destinazioni/metadata, comandi e token opachi restano inerti nel loro dominio.
- F44: HTMLTree e il lookahead dell'enfasi ricevono il subtree della sola
  foglia HTML, prima del feed. Uno span bilanciato non possiede il code
  Markdown successivo. I positivi ChatGPT conservano testo literal, tre
  blocchi, nessuna reference/asset, audit COMPLETE e automatic PASS con
  qualità INDETERMINATE/score5 PROVISIONAL. Code prima dello span e da solo,
  quote e unsafe vero fuori code rimangono controlli. Mapping r009 verso
  raw/char/UTF8 resta invariato; l'owner HTML ancora aperto conserva il dominio
  HTML finito, senza promessa di semantica universale CommonMark.
- F45: matrice finita di 303 casi manuali e due test delle visite dopo il
  primo unsafe, sei producer con Unicode, ordini/chiusure/literal/errori e
  token chiuso/EOF. Protocollo, due guide e report/dati permanenti rettificati.
  F36 B1–B4 deliberatamente UNSUPPORTED: i dati registrano tag/attributi
  riconosciuti dal parser puro, senza secondo feed obbligatorio né cambio
  degli attesi. La divergenza non autorizza tag persi nei fallback Markdown.

Gli argomenti privati `_html_events` e `_inert` del walk sono un trasporto
interno: nessuna nuova API o decisione della nuova architettura. Il dominio
inline è già deciso dal producer, non ricostruito dai marker dopo stripping.
Le barriere sorgente limitano anche il lookahead dei literal incompleti.
Il limite in modalità inline dopo una riga vuota resta len(raw), evitando
un limite scaduto; la modalità sorgente conserva i propri limiti di blocco.
Raw inline `{=html}` resta validato come raw HTML, senza diventare code inerte.
